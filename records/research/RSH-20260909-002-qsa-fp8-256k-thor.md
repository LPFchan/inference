# RSH-20260909-002: QSA FP8 and native 256K context on Jetson Thor
Opened: 2026-09-09 23-50-00 KST
Recorded by agent: codex

## Question

Can current vLLM's Qwen3.8 QSA FP8 cache run on Mangchi's SM110 GPU and serve the model's native 262,144-token context?

## Findings

- The canary image pins vLLM PR #55557 at commit `5fd5dd5cf4ac8e9f09b6fae3f3603e9a3cb88aaa`. It contains the current QSA rewrites plus FP8 E4M3 main-cache support.
- The model runs with NVFP4 expert weights and BF16 compute. Main attention K/V is stored as FP8. The hybrid GDN/Mamba recurrent cache remains float32 under vLLM's `auto` cache setting.
- QSA reads selected FP8 K rows as BF16 and selected V rows as FP16. Per-layer K/V scales are folded into the attention math. This checkpoint does not provide calibrated K/V cache scale tensors, so the runtime uses its default scale and emits an accuracy warning.
- The existing 95.4 GiB BF16 PLE table remains in 128 SSD-backed mmap shards. The rest of the model loaded in 71.11 GiB.
- Mangchi still needs its cooperative top-k exclusion. Current upstream selects that path on SM110, while Thor rejects the launch shape. The canary used vLLM's persistent fallback.

## Capacity and execution results

- `gpu-memory-utilization=0.65` left 2.66 GiB for KV. vLLM estimated a maximum length of 188,160 tokens and correctly rejected 262,144, which needs 3.55 GiB.
- Raising the allocation to 0.67 left 5.19 GiB for cache: 383,350 tokens and 1.46x concurrency at 262,144 tokens.
- QSA decode and sparse-attention warmups passed on SM110, as did the GDN CUDA decode and Triton prefill paths.
- A chat smoke test returned exactly `THOR QSA OK`.
- An exact-ceiling completion with 262,143 input token IDs and one generated token returned HTTP 200. Usage was exactly 262,144 total tokens, with zero preemptions and zero request errors. End-to-end time was 1,642.64 seconds, about 159.6 prompt tokens/s averaged over the request.

## Operational settings

- Image: `mangchi-vllm:thor-qsa-fp8-5fd5dd5`
- Context: `--max-model-len 262144`
- Cache: `--kv-cache-dtype fp8`
- Memory: `--gpu-memory-utilization 0.67`
- Residency reservation: 82 GiB
- Rollback: `mangchi-vllm:thor-v0.29-ple-mmap`, BF16 KV, 131,072 tokens

## Remaining risk

The canary proves build compatibility, cache capacity, kernel execution, short generation, and exact-length prefill. It does not measure long-context recall or the quality effect of default FP8 cache scaling. Watch ordinary conversations for quality regressions and replace the PR pin with its merged commit after revalidation.
